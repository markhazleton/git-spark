## TL;DR

Git Spark is a one-way pipeline: the CLI (or library caller) resolves options, `DataCollector` runs
`git` and parses commits, `GitAnalyzer` turns commits into an `AnalysisReport`, and a format
exporter writes that report. Every metric is computed in `src/core/`; exporters only render.

# Architecture Overview

## Entry Points

| Entry | Path | Role |
|---|---|---|
| CLI binary | `bin/git-spark.js` → compiled `src/cli/commands.ts` (`createCLI`) | Commander program with `analyze`, `health`, `validate`, `init`, `html`, `periods` |
| HTML report command | `src/cli/report-command.ts` | Runs analysis, writes the HTML report, optionally serves or opens it |
| Periods command | `src/cli/periods-command.ts` | Collects commits and compares fixed-length periods |
| Library API | `src/index.ts` | `GitSpark` class plus `analyze()` / `exportReport()` helpers; re-exports types, core, and selected utils |

Options flow through `resolveOptionsWithConfig` (`src/utils/config.ts`, merges `.git-spark.json`)
and `validateOptions` (`src/utils/validation.ts`) before any Git command runs.

## Pipeline

```text
CLI / GitSpark
   │  resolved + validated GitSparkOptions
   ▼
DataCollector (src/core/collector.ts)
   │  git log via GitExecutor (src/utils/git.ts) and its own streaming
   │  spawn('git', args); both use argument arrays
   │  → CommitData[]
   ▼
GitAnalyzer (src/core/analyzer.ts)
   │  authors, files, timeline, risks, governance, health
   │  DailyTrendsAnalyzer (src/core/daily-trends.ts) for daily trends
   │  GitIgnore (src/utils/gitignore.ts) to filter file metrics
   │  → AnalysisReport (src/types/)
   ▼
Exporter (src/output/)
   html | json | markdown | csv | console
```

The `periods` command reuses `DataCollector`, then buckets commits with
`bucketIntoPeriods` / `summarizePeriod` (`src/core/period-summary.ts`) and renders through
`src/output/periods-{console,markdown,html}.ts`.

## Layers

- **`src/core/`** — all measurement. `analyzer.ts` holds `GitAnalyzer`; pure calculations live in
  `analyzer-helpers.ts` (streaks, bursts, gaps, consistency, velocity) and
  `daily-trends-helpers.ts`. Every proxy metric carries a `limitations` object (see the
  analytical-integrity decision in [decisions.md](decisions.md)).
- **`src/output/`** — rendering only. One exporter class per format (`HTMLExporter`,
  `JSONExporter`, `MarkdownExporter`, `CSVExporter`, `ConsoleExporter`). The HTML report is split
  into section builders (`html-author-profiles.ts`, `html-daily-trends*.ts`,
  `html-static-sections.ts`), styles (`html-styles-*.ts`), and inline scripts
  (`html-scripts.ts`); `html.ts` assembles them and computes the SHA-256 hashes used in the CSP.
- **`src/utils/`** — Git execution (`git.ts`), input validation and sanitization
  (`input-validation.ts`, `validation.ts`), config resolution (`config.ts`), `.gitignore`
  matching (`gitignore.ts`), and logging (`logger.ts`).
- **`src/types/`** — the shared contract: options, `CommitData`, `AnalysisReport`, author, file,
  and period types. Core produces these; output consumes them.

## Invariants

- Git is only invoked through `spawn()` with argument arrays, never a shell string.
- Exporters never compute metrics; a new metric is added in `src/core/` and its type in
  `src/types/`, then rendered.
- Progress is reported through the optional `ProgressCallback` passed from the CLI or
  `GitSpark` constructor down to `DataCollector`.
- `src/version.ts` is generated by `scripts/generate-version.js` (run by `prebuild` / `pretest`).
